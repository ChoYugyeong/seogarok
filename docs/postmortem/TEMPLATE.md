# 포스트모템 템플릿

> **이 문서가 답하는 질문:** ① 사고를 "영향 → 타임라인 → 근본 원인 → 재발 방지" 순서로 빠짐없이 정리하려면 어떤 항목이 필요한가? ② 비난 없이(blameless) 시스템 결함을 찾으려면 어떻게 쓰는가? ③ 액션 아이템이 실제로 닫혔는지 어떻게 추적하나?

작성 규칙:

- **비난 없는 회고.** 사람의 실수가 아니라 "그 실수를 막지 못한 시스템/절차"를 고친다.
- **모든 시각은 KST(UTC+9)**로 통일하고, 모르는 시각은 추정하지 말고 `미상`으로 적는다.
- 숫자는 **측정한 것만** 쓴다. 측정 전이면 `TODO(측정 필요)`로 남긴다.
- 액션 아이템은 **담당자·기한·상태**가 없으면 액션이 아니다.
- 사고 규모가 SLO 버짓에 영향을 줬다면 [SRE.md](../SRE.md) §4의 버짓 계산과 연결한다.

- **대응에서 부족했던 점:** (런북 부재, 알림 오탐/미탐, 권한, 접근 경로 등)

## 6. 근본 원인

- **직접 원인:** 무엇이 잘못된 상태를 만들었나.
- **기여 원인:** 그 상태를 막지 못한 절차/도구/설계.
- **구조적 관점:** 같은 실수가 다시 가능한 구조인가? 불가능하게 만들었는가?
- (선택) 5 Whys: `왜? → 왜? → 왜?`로 내려간다.

## 7. 복구와 롤백

- 복구 조치와 검증 방법.
- 롤백했다면 무엇을 어떤 기준으로 되돌렸나.
- 재발 시 복구 시간을 줄이려면 무엇을 자동화해야 하나.
